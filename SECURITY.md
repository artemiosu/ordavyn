# Security policy

Ordavyn is a public experimental repository, not a security certification or production service. No released version is currently supported. See [docs/LOCAL-THREAT-MODEL.md](docs/LOCAL-THREAT-MODEL.md) and [docs/RELEASE-STATUS.md](docs/RELEASE-STATUS.md) for known boundaries.

Report vulnerabilities through [GitHub Private Vulnerability Reporting](https://github.com/artemiosu/ordavyn/security/advisories/new). Do not publish sensitive vulnerability details in a public issue, including exploit details, credentials, private keys, production data, or personal data. No response SLA is promised.

For non-sensitive project matters, contact
[artem@ordavyn.tech](mailto:artem@ordavyn.tech). Do not send vulnerability details
by ordinary email.

Repository checks and CodeQL are bounded engineering controls. They do not establish that the candidate is secure or ready for production.

The prepared [Draft 0.1](spec/ORDAVYN-WIRE-V3.md) records normative security
boundaries. Protocol proposals follow [GOVERNANCE.md](GOVERNANCE.md). Neither
document is an independent audit.
